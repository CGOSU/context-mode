# 设计决策

## 已确认决策

### 2026-11-06：停止推送时自动运行 CI

- 决定：取消 CI 的 push 触发，保留 release.yml 通过 workflow_call 调用。
- 原因：用户不需要每次推送运行这些与程序运行无关的自动检查，且现有检查反复报错；发布流程依赖该工作流。
- 约束：发布时仍会执行全部 CI，现有失败原因并未因此修复；日常推送不再自动测试。

### 2026-11-06：v2 提升为 main

- 决定：保留默认分支名称 `main`，将已验证的 v2 定制作为主线；v1 保留在 `codex/v1-legacy`，不改写其历史。
- 原因：CI、发布路由和保护脚本使用 `main`；直接将临时迁移分支设为默认分支会绕过现有 push CI。
- 约束：分支重命名不移动两个 worktree 或覆盖 v1 未提交修改，Pi 本地包路径保持有效。Issue 自动评论、每日统计提交和每周上游检查仅在上游仓库运行。普通分支推送不触发 npm 发布，源码 Git 安装仍需先构建。

### 2026-11-06：以 v2 为基础保留 Pi 定制

- 决定：在独立 `codex/pi-v2-migration` worktree 中以官方 v2.1.4 为基线，移植必要 Pi 定制，不将 v2 核心逐块拼入 v1。
- 原因：v2 已提供原生进程内 Pi 入口；保持平台适配边界便于后续跟进上游。详细契约见迁移 worktree 的 `docs/architecture/adr/0025-pi-customization.md`。
- 约束：发行版本单独标识为 `2.1.4-pi.1`；保留原 v1 安装与数据，使用单一本地构建包，禁止该 fork 的 ctx_upgrade 自动搬移旧数据；恢复仅依据当前 Pi 分支的持久记录。
