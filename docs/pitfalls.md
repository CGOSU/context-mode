# 开发踩坑记录

本文件按日期倒序记录容易复发且不直观的问题；新增条目插入对应日期位置，最新条目在前。一次性报错、普通开发流水和未经验证的猜测不写入此处。

## 记录格式

每条记录包含：

- 日期：发现或最后验证日期；
- 现象：可观察到的错误或异常行为；
- 根因：经过确认的直接原因；
- 修复：已验证有效的处理方法；
- 验证：复现、测试或检查命令及结果。

## 已知问题

### 2026-11-02：Pi 扩展 reload 后仍读取旧 bundle

- **现象：** Pi 会话 reload 后，context-mode 工具说明仍是旧长文案；磁盘上的 `build/adapters/pi/extension.js` 已包含精简文案。
- **根因：** 已在本机 Pi 1.4.0 加载器与 jiti 2.7.0 上复现：Pi loader 设置 `moduleCache: false`，但 TS extension 重新导出普通 `.js` bundle 时，同一 Pi 进程再次加载仍得到旧模块；新子进程读取到更新后的 bundle。问题位于 Pi 使用 jiti 加载/缓存扩展的链路，不是 context-mode bundle 未构建。jiti 上游有相关 PR #479；修复是否进入当前 Pi/jiti 发布版需后续确认。
- **处理：** 尚未修复。临时绕过方式是彻底退出 Pi 进程再启动；单独 `/reload` 不足以验证 bundle 更新。待 Pi/jiti 上游修复并进入所用版本后重新验证，再决定是否关闭记录。
- **验证：** 在隔离临时目录复现同一进程旧结果、新进程读到新结果；随后确认本地扩展 bundle 含精简说明，Pi reload 后当前工具说明仍为长版。未修改 Pi 全局安装、jiti 依赖或上游代码。
